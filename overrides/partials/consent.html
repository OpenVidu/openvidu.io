{#- Override of Material's partials/consent.html (mkdocs-material 9.7.7). Why: Material renders the consent options pre-ticked and its "Accept" button saves whatever boxes are ticked. Pre-ticked boxes are not valid consent (GDPR Recital 32, CJEU Planet49 C-673/17, AEPD cookie guide), but with the boxes unticked "Accept" would save nothing. Material 9.7.7 has no setting for "accept enables every option", so this partial: - has a single optional purpose, Google Analytics (extra.consent.cookies in mkdocs.yml). With one purpose a checkbox list plus "Save choices" adds nothing, so each purpose is a hidden checkbox that is never ticked before the visitor acts; - "Accept" ticks the hidden checkbox(es), then submits, storing {analytics: true}; - "Reject" is Material's reset button (unticks everything, then saves {}), with the same style and prominence as "Accept"; - when the footer's "#__consent" link reopens the banner, a line says which choice is currently saved, and either button switches it. Saving is still done by Material's unmodified script (partials/javascripts/consent.html), which stores the ticked names with __md_set("__consent", {...}) and restores them into these inputs on load; Google Analytics only loads when that key holds analytics: true. There is no GitHub option: the site sets no repo_url, so Material renders no repository widget and never fetches from api.github.com (the header shows a self-hosted badge). On a theme upgrade, diff this file against the new partials/consent.html. -#}
