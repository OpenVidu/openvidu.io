{#- Override of Material's partials/consent.html (mkdocs-material 9.7.7). Why: Material renders the consent options pre-ticked and its "Accept" button saves whatever boxes are ticked. Pre-ticked boxes are not valid consent (GDPR Recital 32, CJEU Planet49 C-673/17, AEPD cookie guide), but with the boxes unticked "Accept" would save nothing. Material 9.7.7 has no setting for "accept enables every option", so this partial: - shows the options in the same panel as the buttons, never ticked before the visitor acts (a saved choice is restored by Material's own script, partials/javascripts/consent.html); - "Accept all" ticks every option, then submits; - "Reject all" is Material's reset button (unticks everything, then saves), same style as "Accept all"; - "Save choices" submits exactly the boxes the visitor ticked. Saving is still done by Material's unmodified script, which stores the ticked names with __md_set("__consent", {...}); Google Analytics and the GitHub repository stats read that key, and the footer's "#__consent" link still reopens this form showing the saved state.
