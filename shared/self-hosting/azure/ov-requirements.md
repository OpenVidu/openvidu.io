- The [OpenVidu CLI](/docs/self-hosting/openvidu-cli.md#install-the-openvidu-cli).
- An Azure subscription and the [`az` CLI :fontawesome-solid-external-link:{.external-link-icon}](https://learn.microsoft.com/cli/azure/install-azure-cli){:target="_blank"}, **authenticated**: `ov` checks the session with `az account get-access-token`. (`az account show` only reads the local cache, so it can still pass after the sign-in has expired; run `az login` again if the deploy reports the session is gone.) `ov` runs your own client, so your login, subscription and audit trail are the ones that apply. `az` compiles the Bicep itself, so no separate Bicep install is needed.
- A location: `--azure-location`, otherwise `$AZURE_LOCATION`. The resource group defaults to `openvidu-<name>-rg`, or `ov-<name>-rg` when the name is long; `--azure-resource-group` uses one of your own. With the name `openvidu` of these examples, the group is `ov-openvidu-rg` and the Key Vault `ov-openvidu-keyvault`.
- Permission to create resource groups and everything in them: virtual machines, a static public IP, a network security group, a Storage Account with a Blob container, a Key Vault, and for Elastic and High Availability a load balancer and a scale set of media nodes.
- **Quota for the VM size.** The template's default size is `Standard_D4s_v3` (4 vCPU, Standard DSv3 family); the media nodes of an Elastic or High Availability stack default to `Standard_F8s_v2`. Azure caps the vCPUs a subscription runs in a location, per VM family and in total, and a new subscription usually has 10 per family. Before it creates anything, the deploy adds up what its machines need and stops with exit `10` if a family is short. Raise the quota (Azure portal: Quotas > Compute), or pick smaller sizes with `--param instanceType=<size>` on a single node, or `--param masterNodeInstanceType=<size> --param mediaNodeInstanceType=<size>` on Elastic and High Availability.
- For OpenVidu PRO, your **license** (`--openvidu-pro-license`): [create an OpenVidu account :fontawesome-solid-external-link:{.external-link-icon}](/account.md){:target="_blank"} to get one; there is a 15-day free trial. The deploy checks that it is present before it touches your subscription.

You need neither a key pair nor a domain: the deploy generates an SSH key pair for the stack, and without `--domain-name` the stack derives an `sslip.io` name from its public IP (on High Availability, from the load balancer's), so Let's Encrypt has a name to certify on Single Node and Elastic. Use your own domain for anything beyond testing.
