- The [OpenVidu CLI](/docs/self-hosting/openvidu-cli.md#install-the-openvidu-cli).
- A DigitalOcean account and [**Terraform** :fontawesome-solid-external-link:{.external-link-icon}](https://developer.hashicorp.com/terraform/install){:target="_blank"} 1.5.0 or later (1.10.0 with `--remote-state`) on your PATH: `ov` drives your own Terraform, so the provider plugins, the state and the audit trail are the ones that apply.
- `$DIGITALOCEAN_TOKEN`: the API token Terraform authenticates with, with read and write scopes. `ov` proves it with a read of the account before anything is created; DigitalOcean does not report whether a token may write, so a read-only token passes this check and only fails in the apply.
- The Spaces keys `$SPACES_ACCESS_KEY_ID` / `$SPACES_SECRET_ACCESS_KEY`: the deployment's object storage and (DigitalOcean has no managed secret store) its secret store are both a Space, written and read with these. `ov` uses the [`aws` CLI :fontawesome-solid-external-link:{.external-link-icon}](https://docs.aws.amazon.com/cli/latest/userguide/getting-started-install.html){:target="_blank"} as the S3 client to read that Space back.
- A region: `--do-region`, otherwise `$DO_REGION`, otherwise the template's default `ams3`.
- A free Droplet in your account's Droplet limit. A first deploy compares what it creates with the limit and checks the region and the Droplet sizes before touching your account; what does not fit stops it with exit `10`, naming what is short.
- Permission to create Droplets, a firewall, a Space with a bucket-scoped Spaces key, SSH keys and the stack's tag (and, for Elastic and High Availability, a VPC and a load balancer).
- For OpenVidu PRO, your **license** (`--openvidu-pro-license`): [create an OpenVidu account :fontawesome-solid-external-link:{.external-link-icon}](/account.md){:target="_blank"} to get one; there is a 15-day free trial. The deploy checks that it is present before it touches your account.

You need neither a key pair nor a domain: the template generates an SSH key pair for the stack, and without `--domain-name` the stack derives an `sslip.io` name from its public IP (on High Availability, from the load balancer's), so Let's Encrypt has a name to certify on Single Node and Elastic. Use your own domain for anything beyond testing.
