- The [OpenVidu CLI](/docs/self-hosting/openvidu-cli.md#install-the-openvidu-cli).
- A Google Cloud project and [**Terraform** 1.5.0 or later :fontawesome-solid-external-link:{.external-link-icon}](https://developer.hashicorp.com/terraform/install){:target="_blank"} on your PATH: `ov` drives your own Terraform, so the provider plugins, the state and the audit trail are the ones that apply.
- The [`gcloud` CLI :fontawesome-solid-external-link:{.external-link-icon}](https://cloud.google.com/sdk/docs/install){:target="_blank"}, signed in **two ways**: `gcloud auth login`, whose account reads the secrets the stack publishes and the Terraform state bucket, and `gcloud auth application-default login`, the Application Default Credentials Terraform deploys with (one of `$GOOGLE_APPLICATION_CREDENTIALS`, `$GOOGLE_CREDENTIALS`, `$GOOGLE_CLOUD_KEYFILE_JSON` or `$GOOGLE_OAUTH_ACCESS_TOKEN` can give Terraform its own instead). `ov` checks both before it touches the project and exits `10` naming whatever is missing.
- A project id: `--gcp-project`, otherwise `$GCP_PROJECT_ID`, `$CLOUDSDK_CORE_PROJECT`, otherwise what `gcloud` has configured. `--gcp-region` defaults to `europe-west2`; `--gcp-zone` defaults to the region's first zone (`europe-west2-b` with neither given).
- Permission to create Compute Engine instances, a static address, firewall rules, a Cloud Storage bucket, service accounts and Secret Manager secrets.

For OpenVidu **PRO**{ .openvidu-tag .openvidu-pro-tag }, you also need your **license** (`--openvidu-pro-license`): [create an OpenVidu account :fontawesome-solid-external-link:{.external-link-icon}](/account.md){:target="_blank"} to get one, there is a 15-day free trial. The deploy checks that it is present before it touches your project.

You need neither an SSH key nor a domain. On **COMMUNITY**{ .openvidu-tag .openvidu-community-tag } the template generates an SSH key pair for the stack; on **PRO**{ .openvidu-tag .openvidu-pro-tag } the node is reached with `gcloud compute ssh` and no key pair is kept. Without `--domain-name` the stack derives an `sslip.io` name from its public IP (on High Availability, from the load balancer's), so Let's Encrypt has a name to certify on Single Node and Elastic. Use your own domain for anything beyond testing.

!!! warning "Service-account key creation (COMMUNITY)"

    On **COMMUNITY**{ .openvidu-tag .openvidu-community-tag } the template mints a Cloud Storage service-account key that egress uses to upload recordings. An organization policy that blocks key creation (`iam.disableServiceAccountKeyCreation`) stops the apply. Allow key creation in the project, or the deploy cannot finish. **PRO**{ .openvidu-tag .openvidu-pro-tag } does not need it: it reaches Cloud Storage through its S3-compatible API with HMAC keys, so this policy does not block a PRO deploy.
